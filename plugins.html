插件开发

EndBox 的插件是普通 Python 包：一个目录 + plugin.json + 入口文件。它可以往侧边栏加视图、读写自己的数据、 订阅排轴 / 账号的只读快照；宿主负责加载、隔离权限和出问题时的兜底。

01 · 插件能做什么

  • 加视图：注册一个 BaseView 子类，出现在侧边栏「插件」分组。
  • 存数据：每个插件一份私有 JSON（plugin_data/<id>.json），互相不可见。
  • 订阅事件：timeline.*、account.updated、ui.theme_changed。
  • 读快照：排轴 / 账号的只读快照（需要权限）。
  • 上架市场：打包成 zip、写进索引，用户就能在市场里安装 / 更新 / 卸载。

插件拿不到 AppContext、服务对象、主窗口和凭据；只有下面写明的能力。需要联网请自己发请求，并放到 UI 线程之外。

02 · 目录与 plugin.json

plugins/
  hello/
    plugin.json
    plugin.py
    README.md

插件放两个位置，宿主启动时都会扫描：随程序分发的 plugins/，和用户数据目录下的 userdata/plugins/（市场安装 / 手动放）。同一个 id 只加载一次。

{
  "id": "hello",
  "name": "你好插件",
  "version": "0.1.0",
  "author": "你的名字",
  "description": "一个最小示例：注册一个视图，显示一句话。",
  "icon": "spark",
  "entry": "plugin.py",
  "order": 50,
  "min_app_version": "1.1.0",
  "permissions": []
}
  • id必填，字母/数字/_/./-，字母或数字开头，≤64 字符
  • name / description显示名与一句话说明
  • version语义化版本，市场更新比较用
  • entry入口文件，默认 plugin.py，必须在插件目录内
  • min_app_version不满足时标记为加载失败，不拖垮主程序
  • permissions白名单外的权限会被忽略并记日志

03 · 写第一个插件

入口必须定义名为 Plugin 的类（建议继承 EndBoxPlugin）。宿主按「包」加载入口，可以用相对导入拆子文件。

# plugin.py
from endbox.plugins.api import EndBoxPlugin
from endbox.ui.views.base import BaseView
from endbox.ui.kit import Label, Panel


class HelloView(BaseView):
    key = "hello"
    eyebrow = "HELLO"
    title = "你好"
    icon = "spark"
    sidebar_label = "你好"

    def build(self):
        panel = Panel("来自插件的问候", "HELLO")
        panel.add(Label("这个视图是插件注册的。", "muted", wrap=True))
        self._root.addWidget(panel)


class Plugin(EndBoxPlugin):
    def on_load(self):
        self.ctx.register_view(
            HelloView, sidebar_icon="spark", sidebar_label="你好", order=50
        )

    def on_enable(self):
        self.ctx.logger.info("hello enabled")

    def on_disable(self):
        pass

    def on_unload(self):
        pass

生命周期

宿主调用顺序：导入模块 → Plugin(ctx) → on_load() → on_enable()。禁用 / 重新加载 / 退出会调用 on_disable()、on_unload()。

  • on_load()：注册视图、恢复数据、建立订阅；抛异常 = 该插件加载失败并回滚。
  • on_enable() / on_disable()：开关插件；禁用会完整卸载视图与订阅。
  • on_unload()：清理定时器、线程等资源；异常只记日志。

04 · PluginContext API

视图

ctx.register_view(view_cls, sidebar_icon="spark", sidebar_label="计时", order=10)

view_cls 必须是 BaseView 子类；宿主会生成 plugin_<id>_<key> 的新 key，自动出现在侧边栏「插件」分组。

私有存储

ctx.storage.get("timers", [])
ctx.storage.set("timers", timers)
ctx.storage.update({"last_seen": 123})
ctx.storage.delete("legacy_key")
ctx.storage.all()

写入是「临时文件 + 原子替换」；文件损坏时退回空字典，不会让插件加载失败。卸载插件不会自动删私有数据。

事件订阅

sub = ctx.event_bus.subscribe("timeline.state", handler)   # handler(**payload)
sub.cancel()

允许的主题：account.updated、ui.theme_changed，以及所有 timeline.*。订阅其他主题会抛 PermissionError。

只读快照（需要权限）

snapshot = ctx.timeline_snapshot()   # 需要 timeline:read
snapshot = ctx.account_snapshot()    # 需要 account:read

服务未载入时返回空字典 {}；没申请权限会抛 PermissionError。不要把快照写回宿主。

05 · 权限与安全

权限能力数据范围
timeline:readctx.timeline_snapshot()排轴只读快照（时间、编队、事件、Buff）
account:readctx.account_snapshot()账号只读快照（昵称、UID 脱敏、角色列表）
  • 白名单外的权限被忽略并在管理页提示，不会报错。
  • 插件拿不到凭据、主窗口和服务对象；网络请求请自行负责，且不要放在 UI 线程。
  • 删除 / 清空 / 卸载这类破坏性操作必须先用 endbox.ui.kit.confirm 弹确认框。
  • 市场安装只解压、校验 sha256，不执行市场里的代码；真正加载仍由宿主负责。

06 · 本地调试

  1. 把插件目录放到 userdata/plugins/<id>/（用户插件）或仓库的 plugins/<id>/（随程序分发）。
  2. 打开插件管理页 → 刷新扫描；改了代码就点「重新加载」，不需要重启程序。
  3. 加载失败会显示具体原因，同时写进 userdata/logs/endbox.log；先看日志最后几行。
  4. 界面文案放 assets/text/zh-CN.json 的插件段落，用 from endbox.core.text import t 取值；不要硬编码中文。
  5. 视图请复用 endbox.ui.kit 的部件（Panel / Label / CutButton / FieldText / InfoFlag），保持和主程序一致。

07 · 打包与发布到市场

打包

# 打包 plugins/ 与 market/plugins/ 下全部插件，重算 sha256 并更新索引
python tools/pack_plugin.py --all

# 只打一个
python tools/pack_plugin.py --plugin plugins/hello

# 校验索引里的 sha256 / size 与包文件是否一致
python tools/pack_plugin.py --all --check

包结构固定为 <id>/plugin.json、<id>/plugin.py…；打包含固定时间戳，同样源码重复打包 sha256 不变。

市场条目

{
  "schema": 1,
  "name": "EndBox 官方插件市场",
  "updated": "2026-11-15",
  "plugins": [
    {
      "id": "hello",
      "name": "你好插件",
      "version": "0.1.0",
      "author": "你的名字",
      "description": "一句话说明",
      "icon": "spark",
      "category": "工具",
      "tags": ["示例"],
      "download_url": "packages/hello-0.1.0.zip",
      "sha256": "64 位小写十六进制",
      "size": 3409,
      "min_app_version": "1.1.0",
      "permissions": []
    }
  ]
}

发布流程

  1. 改插件源码与 plugin.json 里的 version；
  2. python tools/pack_plugin.py --all；
  3. python run_tests.py tests/test_market.py -q 校验索引与包一致；
  4. 提交 market/index.json、market/packages/*.zip 和插件源码；
  5. 第三方源把索引放到可访问的 HTTPS 地址，用户「插件源 → 添加源」填入即可。

第三方源没有中心化审核：sha256 只能防传输损坏 / 替换，不能证明作者可信。只添加可信来源。

08 · 自带示例

仓库 plugins/ 里有 4 个可以直接读的示例：

完整开发约定（manifest 字段、市场 schema、安全模型）见仓库 docs/plugins.md。

09 · 常见问题

  • 插件不加载看插件管理页原因和 userdata/logs/endbox.log；常见是 manifest 字段写错、entry 不存在、min_app_version 不满足
  • 没有出现在侧边栏视图要在 on_load 里 register_view；禁用状态不会加载
  • 快照是空的对应模块没载入，或没申请权限（会抛 PermissionError）
  • 能调用主程序的内部对象吗不能；插件只有 PluginContext 暴露的这几项能力
  • 能联网吗可以自己发请求；宿主不提供 HTTP 客户端，注意线程与超时
